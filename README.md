# Инструкция и алгоритмический регламент парсинга словаря Мюллера (2021) для формирования датасета Oxford 5000

> **Назначение документа:**  
> Данный документ является исчерпывающим техническим заданием, протоколом и алгоритмическим регламентом для нейросетей, LLM-агентов и автоматических парсеров. Он описывает **детерминированный, воспроизводимый и безошибочный процесс** извлечения, структурирования, очистки и преобразования словарных статей из академического издания словаря В.К. Мюллера в итоговый формат `oxford_5000_2026-08-27.json`.

---

## 1. Входные и выходные спецификации (Contracts)

### 1.1. Входные данные (Inputs)
1. **Первоисточник словаря (PDF / DOCX):**
   - Файл: `Мюллер В.К.,Александрова Т.Е.,Дворкина А.Я.,Романова С.П.-Новый англо-русский словарь...-2021.a4.pdf`
   - Объем: 924 страницы формата A4.
   - Рабочий диапазон страниц: **со страницы 15 (0-индекс 14) по страницу 924 (0-индекс 923)**.
2. **Базовый список слов:** `oxford_5000.json` (4 982 словарные единицы Oxford 5000 / 3000 с уровнями CEFR, транскрипциями и рангами частотности).

### 1.2. Выходной формат (Output JSON Schema)

Целевой файл: `oxford_5000_2026-08-27.json`.

```typescript
interface OxfordWordEntry {
  word: string;              // Заголовочное слово (например, "a", "abandon", "able", "about", "absent", "account", "bird", "break", "can1", "ice", "round")
  frequency_rank: number;    // Частотный ранг Oxford (целое число)
  cefr: "a1" | "a2" | "b1" | "b2" | "c1"; // Уровень CEFR
  phon_br: string;           // Британская транскрипция IPA (/.../)
  phon_n_am: string;         // Американская транскрипция IPA (/.../)
  lists: {
    oxford3000?: boolean;
    oxford5000?: boolean;
  };
  meanings: MeaningEntry[];  // Массив прямых словарных значений слова (без фразовых глаголов и идиом)
  phrases?: PhraseEntry[];   // Массив фразовых глаголов (¬) и идиом (♦)
}

interface MeaningEntry {
  id: number;                // Порядковый номер значения: 1, 2, 3...
  partOfSpeech: CanonicalPOS;// Нормализованная часть речи
  translation: string;       // Русский перевод/дефиниция без служебных помет и без английских фраз
  examples: ExampleEntry[];  // Список контекстных примеров и фраз
  register: string[];        // Массив раскрытых названий регистров/помет на уровне значения
}

interface PhraseEntry {
  id: number;                // Порядковый номер фразы: 1, 2, 3...
  phrase: string;            // Само английское выражение (например, "break in", "to go the round(s)")
  partOfSpeech: CanonicalPOS;// Синтаксическая часть речи фразы (verb, noun, adverb и т.д.)
  translation: string;       // Русский перевод и толкование фразы (для многозначных: 1) ...; 2) ...)
  examples: ExampleEntry[];  // Контекстные примеры использования фразы
  register: string[];        // Стилистические пометы (разговорное, сленг, пословица и т.д.)
}

interface ExampleEntry {
  en: string;                // Английская фраза с раскрытой тильдой (~)
  ru: string;                // Русский перевод примера
  register?: string[];       // Опциональный массив помет, если помета относится строго к данному примеру
}

type CanonicalPOS =
  | "noun"
  | "verb"
  | "adjective"
  | "adverb"
  | "preposition"
  | "conjunction"
  | "pronoun"
  | "numeral"
  | "interjection"
  | "article"
  | "other";
```

## 2. Физическая топология и шрифтовой анализ PDF

### 2.1. Геометрическое колоночное разделение (3 колонки)
Страницы PDF сверстаны строго в **3 вертикальные колонки**. При извлечении токенов через `pdfplumber` или `PyMuPDF` токены фильтруются и группируются по горизонтальным координатам `x0`:

| Колонка | Диапазон координаты `X` |
|---|---|
| **Колонка 1 (левая)** | `35.0 <= x0 < 205.0` |
| **Колонка 2 (средняя)** | `205.0 <= x0 < 369.0` |
| **Колонка 3 (правая)** | `369.0 <= x0 < 590.0` |

*Правило обрезки колонтитулов:* Все токены с `top < 55.0 pt` (верхний колонтитул) и `bottom > PageHeight - 20.0 pt` (номер страницы/нижний колонтитул) должны быть **отброшены**.

### 2.2. Шрифтовая иерархия (Font Hierarchy)

| Элемент статьи | Название шрифта | Размер (pt) | Назначение |
|---|---|---|---|
| **Headword (Заголовок статьи)** | `PragmaticaC-Bold` | `7.0 <= size <= 9.0` | Начало новой словарной статьи |
| **Phrasal Verb (Фразовый глагол вне ♦)** | `NewtonC-Bold` / `PragmaticaC-Bold` | `7.0 <= size <= 8.5` | Полужирное заголовочное слово фразового глагола (со знаком `¬` или `­ ~`) |
| **Homonym (Омоним)** | `PragmaticaC-Bold` / `NewtonC-Bold` | `7.0 <= size <= 9.0` | Римские цифры `I`, `II`, `III` |
| **Phonetics (Транскрипция)** | `MSTT...` / `NewtonC` | `7.0 <= size <= 8.5` | Фонетическая транскрипция в `[...]` |
| **Grammar / Registers (Пометы)** | `*Italic*` (курсив) | `7.0 <= size <= 8.5` | Части речи (`n`, `v`), пометы (`разг.`, `тех.`) |
| **Body (Основной текст и примеры)** | `NewtonC-Regular` | `7.0 <= size <= 8.5` | Переводы, дефиниции, обычные контекстные примеры |

### 2.3. Спецсимволы типографики и OCR-глифы
- **Ударение в словаре:** В PDF представлено нулевым глифом `NewtonC (cid:2)`. Удалять при нормализации.
- **Мягкий перенос строки:** Глиф `NewtonC (cid:4)` или `\u00ad` / `\ue000` / `≅` / `Ч`. Требует обязательной склейки в нормальное русское слово (`рыбака`, `стреляный`, `скандал`).
- **Маркер фразовых глаголов (`¬` / `­ ~`):** Крюк/отрицание — открывает блок глагольных сочетаний и фразовых глаголов (направляется в массив `phrases`).
- **Маркер идиом (`♦`):** Ромб — открывает блок устойчивых идиоматических выражений (направляется в массив `phrases`).

## 3. Разрешение заголовочных слов и политика омонимов (Headword & Homograph Engine)

### 3.1. КРИТИЧЕСКОЕ ПРАВИЛО: Строгая изоляция омонимов (Strict Homograph Isolation)

> **КАТЕГОРИЧЕСКИЙ ЗАПРЕТ:** Запрещено механически объединять несколько неродственных омонимических статей словаря Мюллера (`I`, `II`, `III`) в одну словарную статью Oxford!

1. **Слова с омонимическим индексом в Oxford (`can1`, `wind1`, `wind2`, `row1`, `row2`, `live1`, `live2`, `tear1`, `tear2`, `bear1`, `bear2`):**
   - `can1` $\rightarrow$ сопоставляется **исключительно** со статьей `can I` */kæn/* (*мочь, уметь*); статья `can II` (*бидон, банка, консервировать*) **полностью исключается**.
   - `tear1` $\rightarrow$ сопоставляется **исключительно** со статьей `tear I` */tɪə/* (*слеза*); статья `tear II` (*рвать*) **полностью исключается**.
   - `tear2` $\rightarrow$ сопоставляется **исключительно** со статьей `tear II` */teə/* (*рвать, раздирать*).
   - `bear1` $\rightarrow$ сопоставляется со статьей `bear I` */beə/* (*носить, терпеть, рождать*).
   - `bear2` $\rightarrow$ сопоставляется со статьей `bear II` */beə/* (*медведь*).
2. **Слова без индекса в Oxford, но имеющие омонимы в Мюллере (например, `lead`, `minute`, `a`):**
   - Алгоритм сопоставляет целевую транскрипцию IPA из Oxford (`phon_br` / `phon_n_am`) с фонетикой статей Мюллера:
     - `lead` (Oxford IPA: `/liːd/`, CEFR: A2) $\rightarrow$ отбирается **только** `lead I [li:d]` (*вести, руководить*). Статья `lead II [led]` (*свинец*) **полностью исключается**.
     - `a` (Oxford IPA: `/ə/`, артикль) $\rightarrow$ отбирается **только** `a II` (*неопределенный артикль*), омоним `A, a I` (*буква алфавита*) **исключается**.

## 4. Синтаксический разбор внутренней структуры статьи

### 4.1. Иерархия уровней статьи
1. **Уровень 1: Макросекции частей речи.**  
   Формат: `1. n ...`, `2. v ...`, `3. a ...` (или неномерной заголовок `n ... 2. v ...`).  
   *Критическое правило:* При переходе к следующей части речи (`2. v`, `2. n`) строка **строго разделяется на самостоятельные объекты `meanings`** с соответствующим `partOfSpeech`.
2. **Уровень 2: Номера значений внутри части речи.**  
   Формат: `1) ...`, `2) ...`, `3) ...`.  
   *Критическое правило (Preservation of Numbered Senses):* Каждый номерной пункт (`1)`, `2)`, `3)`) **обязан формировать отдельный объект `MeaningEntry`**. Категорически запрещено проглатывать номерной пункт или превращать его целиком во фразу массива `phrases` только потому, что внутри него содержится пример с тильдой (как в `accessible 2) поддающийся; податливый; ~ to bribery продажный` $\rightarrow$ обязано быть 2 отдельных значения!).
3. **Уровень 3: Блок фразовых глаголов (`¬`).**  
   Отсекается и направляется в массив `phrases` с `partOfSpeech: "verb"`.
4. **Уровень 4: Блок идиом и устойчивых словосочетаний (`♦`).**  
   Отсекается и направляется в массив `phrases`.

### 5.3. Разграничение помет значения (Sense-level) и помет примера (Example-level)

> **КРИТИЧЕСКОЕ ПРАВИЛО:**
> 1. **Помета на уровне значения (`MeaningEntry.register`):** Если помета в словаре стоит перед общей дефиницией всего значения (например: `1) воен. патрон; выстрел; очередь`), она относится ко всему значению и помещается в `meaning.register: ["военное"]`.
> 2. **Помета на уровне примера (`ExampleEntry.register`):** Если общее значение слова нейтрально (например, `about` $\rightarrow$ *«в обратном направлении»*, `academy` $\rightarrow$ *«учебное заведение»*, `angle` $\rightarrow$ *«угол»*), а помета относится к конкретному примеру (`about face! воен. кругом!`, `Military Academy воен. военное училище`, `angle of attack ав. угол атаки`):
>    - С базового значения пометы снимаются (`meaning.register: []`), сохраняя его нейтральность.
>    - У конкретного примера создается локальный массив `register: ["военное"]`.

### 5.4. Составные и множественные пометы (Chained / Multiple Registers)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Если в словаре дефиниция сопровождается несколькими пометами через запятую (например: `3) астр., геол. неровность поверхности, складка`, `воен., мор.`, `амер., разг.`):
> - Все пометы последовательно извлекаются и помещаются в массив `register: ["астрономия", "геология"]`.
> - Из строки `translation` полностью вырезаются все сокращения и ведущие знаки препинания, оставляя чистый русский текст: `"translation": "неровность поверхности, складка"`.

## 6. Парсинг дефиниций, предлогов, множественного числа, фразовых глаголов и идиом

### 6.1. КРИТИЧЕСКОЕ ПРАВИЛО: Приоритет описательной дефиниции (Prepositional & Functional Definition Rule)

> **КАТЕГОРИЧЕСКИЙ ЗАПРЕТ:** Запрещено подставлять перевод первого примера (`examples[0]['ru']`) в поле `translation`, если значение содержит семантическое толкование («указывает на...», «выражает...», «придаёт значение...»)!

1. Если смысловой сегмент начинается с конструкции вида `указывает на [описание] [русские предлоги]:`:
   - Вся вводная формулировка до двоеточия или первого примера извлекается как **канонический `translation`**.
2. Все последующие английские словосочетания с переводом отделяются от дефиниции и помещаются в массив `examples`.

---

### 6.2. КРИТИЧЕСКОЕ ПРАВИЛО: Изоляция английских фраз от русского перевода (Zero-English in Translation)

> **КАТЕГОРИЧЕСКИЙ ЗАПРЕТ:** Строка `translation` обязана содержать **исключительно русский перевод**! Запрещено оставлять внутри строки `translation` (как в начале подпунктов, так и в конце после точки с запятой) английские обороты примеров (например: `to break into smb.'s time`, `to assert oneself`, `acid test`, `blood bank`, `to weigh anchor`).

1. **Разрыв по буквам подпунктов (`а)`, `б)`):** Запрещено создавать новые значения `meanings` для буквенных подпунктов примеров. Все подпункты объединяются в перевод соответствующего примера в массиве `examples`.
2. **Очистка встроенных примеров:** Любое английское выражение `to ...` внутри дефиниции отделяется от русского текста и переносится в массив `examples`, оставляя в `translation` чистый русский перевод.

---

### 6.3. Структурирование фразовых глаголов (`¬`) и идиом (`♦`) в массив `phrases`

> **КРИТИЧЕСКИЙ РЕГЛАМЕНТ:**  
> Массив `phrases: [...]` содержит **СТРОГО два типа языковых единиц**:
> 1. **Фразовые глаголы (Phrasal Verbs):** аналитические глагольные лексемы вида `<глагол> + <послелог>`.
> 2. **Идиомы и фразеологизмы (Diamond Idioms):** устойчивые неделимые фразеологические обороты, пословицы и поговорки из специального блока ромбика `♦`.

#### 6.3.1. Критерий А: Фразовые глаголы (Phrasal Verbs)
Выражение попадает в `phrases` (с `partOfSpeech: "verb"`), если:
- **Типографика и маркеры:** Вне блока ромбика `♦` заголовок фразового глагола напечатан **полужирным шрифтом (`NewtonC-Bold`)** и предваряется знаком `¬` или маркером переноса `­ ~ [послелог]` / `- ~ [послелог]`.
- Либо представляет собой конструкцию `<глагол> + <послелог>` (`break in`, `break down`, `give up`, `take off`, `ice up`, `look after`, `settle down`, `pick up`), где послелог входит в замкнутый список фразовых частиц (`PHRASAL_PARTICLES`):  
  `in`, `out`, `up`, `down`, `off`, `on`, `away`, `back`, `by`, `over`, `through`, `about`, `across`, `ahead`, `along`, `around`, `forth`, `forward`, `into`, `onto`, `together`, `under`, `apart`, `aside`, `behind`, `between`, `round`.

#### 6.3.2. Критерий Б: Идиомы и фразеологизмы (Diamond Idioms)
Выражение попадает в `phrases`, если:
- В оригинале статьи Мюллера оно расположено **СТРОГО внутри специального блока ромбика `♦`** (как срединного, так и заключительного).
- *Типографическое правило ромбика:* Внутри блока `♦` идиомы отделяются друг от друга точкой с запятой и **не требуют обязательного полужирного выделения** — сам знак `♦` служит детерминированным маркером начала блока фразеологии.
- Английский текст выражения (или его форма с тильдой `~`) **буквально содержится в сегменте текста между символом `♦` и началом следующей части речи / концом статьи**.
- *Примеры:* `birds of a feather flock together`, `to break the ice`, `what cannot be cured must be endured`, `a little bird told me`, `Mr. Jones is not about`, `about right`, `what are you about?`.

#### 6.3.3. Критерий отсева обычных словосочетаний (False Phrases Exclusion):
- **Типографический критерий:** Все контекстные примеры употребления и модели управления вне блока `♦`, напечатанные **обычным шрифтом (`NewtonC-Regular`)** без полужирного выделения и без маркера `¬` (например: `able to pay` $\rightarrow$ `able`, `accessible to bribery` $\rightarrow$ `accessible`, `admission by ticket` $\rightarrow$ `admission`, `area under crop` $\rightarrow$ `area`, `rich in minerals` $\rightarrow$ `rich`, `reduction in rank` $\rightarrow$ `reduction`, `quick to learn` $\rightarrow$ `quick`), **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО выносить в `phrases`**!
- Все такие сочетания обязаны находиться в массиве `examples: [...]` соответствующего прямого значения в `meanings`.
- Для многозначных фразовых глаголов и идиом значения нумеруются: `"translation": "1) [значение 1]; 2) [значение 2]"`.

### 6.4. Стандартизация семантического множественного числа (`при англ. мн. ч.: `)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Если в словаре Мюллера значение закреплено за формой множественного числа (`pl`, `(обыкн. pl)`, `собир. pl`), запрещено засорять перевод английскими словами или додумывать синонимы. Значение оформляется строго детерминированным префиксом:

1. **`pl`** $\rightarrow$ `translation: "при англ. мн. ч.: [буквальный русский перевод]"`
2. **`обыкн. pl`** $\rightarrow$ `translation: "обыкн. при англ. мн. ч.: [буквальный русский перевод]"`
3. **`собир. pl`** $\rightarrow$ `translation: "собир. при англ. мн. ч.: [буквальный русский перевод]"`
4. **`часто pl`** $\rightarrow$ `translation: "часто при англ. мн. ч.: [буквальный русский перевод]"`
5. **`без измен. в pl`** $\rightarrow$ `translation: "без измен. при англ. мн. ч.: [буквальный русский перевод]"`

### 6.5. Изоляция срединных блоков идиом (`♦`) в многочастеречных статьях

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Если в словарной статье ромбик `♦` расположен в середине статьи между частями речи (например: `1. n ... ♦ [идиомы] 2. v ...` как в словах `ice`, `act`, `account`, `air`, `ball`, `balance`, `round`), **запрещено нарезать из блока идиом значения существительного в массив `meanings`!**

1. Все блоки `♦` (независимо от их положения в статье) извлекаются и переносятся **исключительно в массив `phrases`**.
2. В основном массиве `meanings` остаются **строго прямые значения частей речи слова**.

### 6.6. Морфологическое разворачивание тильды (`~`)
Тильда (`~`) замещает основу заголовочного слова с учетом морфологии английского языка:

```python
def expand_tilde(text: str, base_word: str) -> str:
    stem = re.sub(r"[1-9]$", "", base_word).strip()
    y_stem = stem[:-1] if stem.endswith("y") and len(stem) > 1 and stem[-2] not in "aeiou" else stem
    e_stem = stem[:-1] if stem.endswith("e") else stem
    replacements = [
        ("~est", stem + "est"),
        ("~er", stem + "er"),
        ("~ies", y_stem + "ies"),
        ("~ied", y_stem + "ied"),
        ("~ing", e_stem + "ing"),
        ("~ed", e_stem + "ed"),
        ("~d", e_stem + "d"),
        ("~s", y_stem + "ies" if stem.endswith("y") and len(stem) > 1 and stem[-2] not in "aeiou" else stem + "s"),
        ("~'s", stem + "'s"),
        ("~", stem),
    ]
    for pattern, repl in replacements:
        text = text.replace(pattern, repl)
    return text
```

### 6.7. Стандартизация атрибутивного употребления существительных (`attr.` $\rightarrow$ `в роли определения к другому слову`)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Если пункт статьи начинается с пометы `attr.:` или `attr.` без отдельного русского прилагательного и сопровождается составными терминами (например, `accident 5) attr.: ~ insurance...; ~ prevention...; ~ rate...`):
> 1. В поле `translation` записывается стандартизированная дефиниция:  
>    `"translation": "в роли определения к другому слову"`
> 2. Все приведенные устойчивые словосочетания и сложные термины направляются в массив `examples: [...]` данного значения.

### 6.8. Стандартизация знака приблизительного / образного эквивалента (`≅` $\rightarrow$ `≈`)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Знак `≅` в словаре Мюллера означает: *«данный русский эквивалент лишь приблизительно передает значение английского выражения»* (образный идиоматический аналог, а не дословный перевод).
> 1. В итоговом датасете печатный знак `≅` стандартизируется в общепринятый Unicode-символ **`≈`** (U+2248).
> 2. Знак **`≈`** сохраняется в начале русского перевода фразы или примера:  
>    `"translation": "≈ в семье не без урода; скандал в благородном семействе"`

---

### 6.9. Извлечение встроенных контекстных примеров (Embedded Examples Extraction)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Если внутри словарного пункта после точки с запятой или двоеточия следует английское выражение с контекстным переводом (например, `рельс; the train left the ~s поезд сошёл с рельсов`, `достигать, добиваться; to ~ one's purpose достичь цели`):
> 1. **Запрещено** оставлять английские фразы и их переводы внутри строки `translation`.
> 2. В поле `translation` остается **строго чистая русская дефиниция** (`"translation": "рельс"`, `"translation": "достигать, добиваться"`).
> 3. Английский пример отделяется, тильда (`~`) морфологически разворачивается (`the train left the rails`), а пара `en` + `ru` направляется в массив **`examples: [...]`** данного значения.
> 4. Любые родительские пометки в скобках с тильдами (`(тж. letter of ~)` $\rightarrow$ `(тж. letter of advice)`, `(тж. big ~)` $\rightarrow$ `(тж. big cheese)`) внутри `translation` обязаны быть морфологически раскрыты.

### 6.10. Раздельная обработка омонимов Оксфорда и частей речи (Homonyms & Part-of-Speech Invariants)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Омонимы и разные части речи из списка Oxford 5000:
> - `IT` (B1 noun) vs `it` (A1 pronoun)
> - `March` (A1 noun) vs `march` (A2 verb/noun)
> - `May` (A1 noun) vs `may` (A2 modal verb)
> - `house` (A1 noun) vs `house` (B2 verb)
> - `live` (A1 verb) vs `live` (B1 adj) vs `live` (B2 adv)
> - `minute` (A1 noun) vs `minute` (B2 adj)
> - `use` (A1 verb) vs `use` (A2 noun)
> - `wind1` (A1 noun) vs `wind2` (B1 verb)
>
> 1. **Категорически запрещено объединять омонимы в один JSON-объект.** Каждый словарный вход Оксфорда обязан сохраняться отдельной записью с его частотным рангом и уровнем CEFR.
> 2. **Запрещено сокращать или додумывать значения.** Каждый омоним наполняется строго соответствующей частью статьи Мюллера **в полном академическом объеме** (все нумерованные значения, примеры, регистры и фразеологизмы).
> 3. **Запрещено добавлять выдуманные пометы (Zero Hallucinated Registers):** пометы добавляются в `register: [...]` только если они явно и буквально присутствуют в печатном первоисточнике (`поэт.`, `воен.`, `муз.`, `мед.`, `тех.` и т.д.).

---

### 6.11. Целостность многозначных примеров и защита от разрыва буквенных подпунктов (Multi-Sense Examples Integrity)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Если контекстный пример или устойчивое выражение внутри словарного пункта имеет несколько буквенных вариантов перевода (например, `to give good ~ а) дать полную меру; б) воздать полной мерой; заплатить с лихвой`):
> 1. **Категорически запрещено** отрезать пункт `б)` и оставлять его хвостом в строке `translation`.
> 2. Все буквенные подпункты `а)`, `б)`, `в)` обязаны **воссоединяться внутри поля `ru` родительского примера** в объекте `examples: [...]`.
> 3. Буквенная нумерация `а)`, `б)` внутри примера стандартизируется в числовую: `"ru": "1) дать полную меру; 2) воздать полной мерой; заплатить с лихвой"`.
> 4. В поле `translation` значения остается **строго дефиниция самого базового значения** (`"translation": "мера; единица измерения"`).

---

### 6.12. Чистота поля перевода примеров (`examples[].ru`) и вынос стилистических помет

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Все отраслевые, стилистические и региональные пометы (`ком.`, `воен.`, `мор.`, `ав.`, `ж.-д.`, `тех.`, `физ.`, `разг.`, `сл.`, `спорт.`, `эл.`, `уст.` и др.), стоящие в начале русского перевода примера:
> 1. Обязаны быть полностью извлечены из текста `ru` и декодированы по `REGISTER_MAP`.
> 2. Направляются в массив **`examples[].register: ["коммерческое"]`**.
> 3. В поле `examples[].ru` сохраняется **строго чистый русский перевод** без сокращений и помет.

---

### 6.13. Орфографическая нормализация сложных дефисных слов (Russian Hyphenated Compounds)

> **КРИТИЧЕСКОЕ ПРАВИЛО:** Все сложные существительные, наречия, местоимения и предлоги обязаны сохранять нормативные дефисы русского языка:
> - Должности и профессии: `инженер-механик`, `инженер-конструктор`, `премьер-министр`, `генерал-майор`, `член-корреспондент`, `пресс-секретарь`.
> - Составные термины: `пресс-конференция`, `вагон-ресторан`, `яхт-клуб`, `плащ-палатка`.
> - Стороны света: `северо-запад`, `северо-восток`, `юго-запад`, `юго-восток`.
> - Наречия с приставкой `по-`: `по-русски`, `по-английски`, `по-немецки`, `по-французски`, `по-видимому`, `по-прежнему`, `по-новому`, `по-старому`, `по-моему`, `по-твоему`, `по-нашему`, `по-вашему`, `по-своему`.
> - Неопределенные местоимения и наречия: `что-то`, `кто-то`, `где-то`, `куда-то`, `когда-то`, `какой-то`, `что-нибудь`, `кто-нибудь`, `где-нибудь`, `как-нибудь`.
> - Предлоги и идиомы: `из-за`, `из-под`, `точь-в-точь`, `тет-а-тет`.

## 7. Комплекс очистки текста и ликвидации OCR-дефектов (Zero-Artifact Policy)

1. **Интеллектуальная склейка переносов слов:**
   - Паттерн `(?<=[А-Яа-яA-Za-z])-[\s\n]*≅?[\s\n]*(?=[а-яa-z])` заменяется на слитное написание (`\1\2`), восстанавливая слова `рыбака`, `стреляный`, `скандал`.
   - Защита дефисных слов: `что-либо`, `кого-либо`, `из-за`, `из-под`, `где-то`, `во-первых`, `северо-западный`, `Санкт-Петербург`, `Ла-Манш` обязаны сохранять дефис.
2. **Тотальное восстановление дефисных местоимений и наречий:**
   - Все составные местоимения и наречия со служебными постфиксами `-либо`, `-то`, `-нибудь` (`кем-либо`, `что-либо`, `кому-либо`, `где-то`, `по-своему`, `из-за`) **обязаны писаться через дефис**.
   - Точки от словарных сокращений (`кем-л.` $\rightarrow$ `кем-либо`) внутри скобок и предложений удаляются: `(to — перед кем-либо)`.
3. **КРИТИЧЕСКАЯ ЗАЩИТА: Неприкосновенность русских корней и идиом при вырезании регистров:**
   - Категорически запрещено удалять подстроки стилевых сокращений (`уст.`, `собир.`, `мор.`, `мед.`, `воен.`) из состава русских слов и устойчивых выражений:
     - Нельзя вырезать `уст.` из фразеологизма **«из уст в уста»** (запрещено оставлять огрызки вида *«передаваться из в а»*).
     - Нельзя вырезать `мор.` из слов **«моря»**, **«в море»** (запрещено оставлять *«все я и океаны»*, *«выходить в е»*).
     - Нельзя вырезать `собир.` из слова **«собираться»** (запрещено оставлять *«аться уходить»*).
4. **Нормализация пунктуации:**
   - Преобразовать многоточия `. . .` в `...`.
   - Очищать висячие точки, двоеточия, точки с запятой и запятые в начале и конце строк `translation`.
5. **Удаление служебного мусора:**
   - Запрещено наличие в выходном JSON строк `<i>`, `</i>`, `(cid:*)`, `\ue000`, `\u00ad`, `\u200b`, `\ufeff`, `♦`, `¬`, `≅`.

## 8. Протокол валидации и проверки качества (QA Rules)

Перед фиксацией готового файла нейросеть / скрипт обязаны проверить следующие инварианты:

```python
def validate_dataset(entries: list[dict]) -> list[str]:
    errors = []
    if len(entries) != 4980:
        errors.append(f"Expected exactly 4980 entries, got {len(entries)}")
        
    for entry in entries:
        word = entry.get("word")
        meanings = entry.get("meanings", [])
        if not meanings:
            errors.append(f"Word '{word}' has 0 meanings")
            
        for idx, m in enumerate(meanings, start=1):
            if m.get("id") != idx:
                errors.append(f"Word '{word}': meaning id is {m.get('id')}, expected {idx}")
            if not m.get("translation") and not m.get("examples"):
                errors.append(f"Word '{word}': meaning {idx} is completely empty")
            if not isinstance(m.get("register"), list):
                errors.append(f"Word '{word}': register must be a list")
            if m.get("partOfSpeech") == "other":
                errors.append(f"Word '{word}': meaning {idx} has uncanonical POS 'other'")
            for ex in m.get("examples", []):
                if not ex.get("en") or not ex.get("ru"):
                    errors.append(f"Word '{word}': meaning {idx} has empty example")
                if "register" in ex and not isinstance(ex["register"], list):
                    errors.append(f"Word '{word}': meaning {idx} example register must be a list")
                
        # Валидация массива идиом и фразовых глаголов (phrases)
        for p_idx, p in enumerate(entry.get("phrases", []), start=1):
            if p.get("id") != p_idx:
                errors.append(f"Word '{word}': phrase id is {p.get('id')}, expected {p_idx}")
            if not p.get("phrase") or not p.get("translation"):
                errors.append(f"Word '{word}': phrase {p_idx} missing phrase or translation")
            if not p.get("partOfSpeech"):
                errors.append(f"Word '{word}': phrase {p_idx} missing partOfSpeech")
            for ex in p.get("examples", []):
                if not ex.get("en") or not ex.get("ru"):
                    errors.append(f"Word '{word}': phrase {p_idx} has empty example")
                
    return errors
```
