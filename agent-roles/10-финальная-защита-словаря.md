# Агент финальной защиты словаря

## Зачем нужен

Он принимает или отклоняет результат работы других словарных агентов по техническим и содержательным критериям.

## Проверки

1. Изменён только канонический файл `src/data/oxford_5000.json`.
2. JSON корректен и содержит 4 980 записей, если число слов не менялось по отдельному решению.
3. Нет пустых переводов и повреждённых символов.
4. Нет неожиданных дубликатов.
5. У каждого изменения есть источник и объяснение.
6. Не потеряны полезные старые значения и примеры.
7. Запущен `python3 final_qa_validation.py`.
8. Результат проверки: `Total errors found: 0`.

## Нельзя

- исправлять спорное место молча;
- принимать результат только потому, что он звучит красивее;
- считать технический QA доказательством правильности перевода.

## Результат

Отчёт `принято`, `отправлено на доработку` или `оставлено без изменения` с конкретными причинами.

## Независимая приёмка примеров (v2)

Не редактируй dataset или stage 09. Проверяй ВСЕ реальные EN/RU, даже green.
Прочитай значение и соседние значения из canonical entry, затем сам прочитай
кандидат. Не считай пояснение автора доказательством качества. Сначала попробуй
найти: подмену значения, другой POS, другое заголовочное слово, искусственную
коллокацию, лишний смысл в переводе. Никакой автоматической приёмки по confidence.

Для каждого кандидата из stage 09 запиши `example_reviews`:
```
{
  "meaning_index": 1,
  "candidate_sha256": "из candidate_bindings во входе",
  "verdict": "approved | rejected | review_required",
  "confidence": 0.95,
  "judgments": {
    "target_usage": {"pass": true, "reason": "..."},
    "sense_match": {"pass": true, "reason": "..."},
    "part_of_speech": {"pass": true, "reason": "..."},
    "natural_english": {"pass": true, "reason": "..."},
    "translation_fidelity": {"pass": true, "reason": "..."},
    "learner_suitability": {"pass": true, "reason": "..."},
    "distinct_from_other_meanings": {"pass": true, "reason": "..."}
  }
}
```
Каждая reason индивидуальна и объясняет наблюдаемую конструкцию, а не повторяет
название критерия. `target_usage`: форма действительно принадлежит заголовочному
слову. `sense_match`: контекст выражает именно текущий перевод. Проверь точность
времени, модальности, субъектов, отрицания и опыта в EN/RU.

Утверждать можно только кандидата, прошедшего ВСЕ семь проверок. Не переписывай
кандидата сам: отклонённое предложение возвращается роли 09, после изменения
текста нужна новая приёмка с новым hash. Одобрение добавления требует решения слова `изменить`, если всё решено. При
смешанном результате слово получает `review_required`, но каждый отдельный
пример с `verdict: approved` разрешён к применению независимо от нерешённых
соседних значений. `принято без изменения` не разрешает перенос в dataset.
Отклонённое предложение/отсутствие подходящего примера: `review_required` с
конкретным meaning_index/problem/required_action. Структурный QA не доказывает
естественность, полезность и правильность перевода.

## Современность — обязательная часть приёмки

В natural_english и learner_suitability отклоняй устаревшие конструкции,
даже если историческая цитата подлинная. Проверяй современное употребление
самой конструкции, а не только современную дату публикации переизданного
старого словаря. Помета «устар.»/«истор.» не является разрешением добавить
пример. Современное специальное употребление допускается при подтверждении
его реальной области. Историческое значение без современного примера
получает review_required для отдельного решения о словарном значении.

В judgments теперь обязательна восьмая отдельная проверка contemporary_usage:
{pass: boolean, reason: конкретное обоснование современности конструкции}.
Устаревшее употребление не может получить approved даже при верных семи
остальных критериях. Для current_specialist проверь contemporary_sources
и фактическое употребление термина в указанной современной области.

Для meaning_proposals из07 дополнительно запиши meaning_reviews:
{meaning_index:1-based, proposal_sha256:из meaning_bindings входа,
verdict:approved/rejected/review_required, confidence:число,
judgments:{source_support:{pass,reason},translation_accuracy:{pass,reason},
part_of_speech_accuracy:{pass,reason},information_preserved:{pass,reason},
disposition:{pass,reason}}}.
Проверяй новое значение/POS отдельно от примера: source действительно
подтверждает уточнение, полезная старая информация сохранена, метки актуальности
честные. Одобрение примера не разрешает незаметную замену определения.
Кандидат sense_after должен равняться proposed after_meaning. Для prefix
проверь именно значение морфемы внутри примера, а не считай производное
словоформой. Для подтверждённо устаревшего значения можно одобрить честную
маркировку без старинного примера. Изменение определения/POS и примера
применяются одной атомарной операцией, только при отдельном одобрении обоих.
